# DSH 検索プロバイダー

DeepSeek Harnessで検索先を選ぶプラグインです。Keenable、Nimble、TinyFish、Parallel、Exa、Brave、Perplexityに対応します。

FxTwitterの `x_search` で、Xの投稿検索と投稿URLからの本文取得もできます。

通常の `web_search` はDSHの既存ツールを使います。複数クエリの処理、結果カード、出典、会話履歴、システムプロンプトを維持します。対応するDSHは `0.2.1-alpha.2` 以上、`0.3.0` 未満です。`0.2.1-alpha.3` と、それ以降の `0.2.x` prerelease を含みます。`0.3.0` の prerelease は含みません。

## インストール

```sh
dsh plugin --profile web add -w github:Aero123421/dsh-search-providers
```

DSHを再起動し、「設定 → 検索プロバイダー」を開きます。

表示言語はDSHの言語設定に従います。このプラグインは新しい言語を追加しません。DSH `0.2.1-rc.2` には英語と中国語があり、日本語の表示には [dsh-japanese](https://github.com/Aero123421/dsh-japanese) が必要です。

ビルド済みファイルを含むため、インストール時のビルドは不要です。`dist` の依存パスはパッケージマネージャで変わるため、作り直すときは `npm ci` のあとで `npm run build` します。版を固定する指定例は `github:Aero123421/dsh-search-providers#v0.4.1` です。該当タグの公開後に利用できます。公開済みのタグと配布ファイルは[Release一覧](https://github.com/Aero123421/dsh-search-providers/releases)で確認してください。

## 使い方

1. プロバイダーの「APIキーを保存」を押します。Keenableはキーなしでも使えます。
2. プロバイダーを有効にし、「通常検索に使う」を押します。
3. 必要なら「検索設定」で地域・言語・モード・ドメイン・日付等を保存します。空欄は従来の既定値を維持します。
4. 必要な追加機能を「使う機能を選ぶ」で有効にします。

標準 `web_search` は選んだ1社と、その社の保存済み検索設定を使います。呼出しごとに条件を変える場合は、別の追加機能 `search_web` または対応する専門検索の `options` を使います。指定したフィールドだけが保存値を上書きし、未指定の値は引き継ぎます。未対応の条件は黙って削除しません。[設定・モード・APIへのマッピング](docs/search-options.md)

HTTP 429で他社へ切り替えるのは、保存済み／呼出しの検索条件がない初回検索だけです。有効で同じ検索に対応し、保存済み検索条件もない別社を一覧順に1回ずつ試します。国だけ・モードだけでも条件があれば切り替えません。認証失敗、無効、未対応指定、429以外では切り替えず、同じ提供元への自動再送もしません。本文取得、バッチ本文取得、サイト一覧、X検索、続き取得は切り替えません。無効な提供元や高額モードを自動で有効にはしません。切り替え先にも、その社の利用枠や料金がかかります。

モード・結果件数・追加ページ・抽出URL数で料金が変わる場合があります。高額／長時間モードへの自動変更はしません。2026-10-18に確認したBrave公式FAQでは、単独の無料プランはなく、各プランに毎月$5のクレジット（Searchで約1,000クエリ）があり、カードが必要です。残高$0の拒否が429とは限りません。同FAQはAPIデータの保存を禁止し、保存が必要な場合は相談を求めています。DSHの会話履歴に保存する利用を含め、各社の料金・保存権・第三者コンテンツの利用条件を確認してください。このプラグインは保存や画像・本文の再利用の権利を付与しません。[Brave FAQ](https://api-dashboard.search.brave.com/documentation/resources/help-feedback) · [契約と対応範囲](docs/providers.md)

追加機能は通常検索とは別に提供元を選べます。同じ機能で別の提供元を選ぶと、以前の選択を置き換えます。

プロバイダーを無効にしても、APIキーと機能の選択は残ります。無効にしたプロバイダーの追加ツールはエージェントから外れます。既定のプロバイダーを無効にすると、通常検索はエラーになります。

APIキーはDSHの資格情報ストアに保存します。画面にキーの値は返しません。保存済みのキーがない場合は各社の環境変数を使います。

## 追加機能

| 機能 | 提供元 |
| --- | --- |
| 条件付きWeb検索（`search_web`） | Keenable、Nimble、TinyFish、Parallel、Exa、Brave、Perplexity |
| ニュース検索 | Nimble、TinyFish、Exa、Brave |
| 論文検索 | Nimble、TinyFish、Exa |
| コード検索 | Nimble |
| 人物検索 | Exa、Perplexity |
| 企業検索 | Exa |
| 画像・動画検索 | Brave |
| ページ本文取得（`extract_web_page`） | Keenable、Nimble、TinyFish、Parallel、Exa |
| 複数ページ本文取得（`extract_web_pages`） | TinyFish、Parallel、Exa |
| サイト内のページ一覧 | Nimble |
| X検索・投稿URLの本文取得 | FxTwitter |

追加機能は最初はすべて無効です。有効な機能だけエージェントにツールとして渡します。ニュース・論文検索も追加ツールとして登録し、標準 `web_search` の入力を変えません。`web_fetch` もDSH標準のままです。

本文取得は独立した `extract_web_page` です。外部APIが対象ページのHTTPステータスを返さない場合があるため、標準 `web_fetch` の代わりにはしません。外部の調査エージェント、ブラウザ操作、クロール、定期監視は含めていません。

論文の著者・年・DOI・PDF・被引用数や、画像のURL・寸法・サムネイル、動画の時間等は、提供元が返したものだけを検証して保持します。公開日・更新日・取得日・インデックス化日時を区別します。追加検索は型付きフィールドとメタデータJSONで返し、標準DSHで残らない項目の一部はラベル付き注記として既存の抜粋・出典カード・履歴用情報にも載せます。専用の新しいカードではなく、量の上限によりメタデータも省略されます。[メタデータの意味と上限](docs/providers.md#日付論文メディア情報)

### 複数URLの本文取得

```js
extract_web_pages({ urls: ["https://example.com/guide", "https://example.org/article"] })
```

1〜10 URL、各本文100,000文字・本文合計200,000文字までです。重複URLは提供元へ1度だけ送り、出力では入力順に成功／エラーを返します。HTTP応答の2MiB上限を超えた場合は呼出し全体が失敗します。URL数に応じて課金され得るため、1ツール呼出しが1件分の料金とは限りません。取消後の返金は保証しません。[バッチの制限と部分失敗](docs/providers.md#本文の単一取得とバッチ取得)

### 検索の続きを取得する

追加検索が `nextPage` を返した場合、同じツールへ同じ `query` と `next_page` を渡すと、次の1ページを要求できます。`options`、`max_results`、Xの `sort` は併記しません。TinyFish、BraveのWeb／ニュース／動画、FxTwitterのキーワード検索が対象です。Brave画像や他社には使えません。

ハンドルは15分・提供元ごと100件の一時保存で、再起動や解除で失効します。自動の全件取得や続きの他社切り替えはなく、各ページに料金・利用枠がかかります。重複URLを省きますが、順位・網羅性は保証しません。[ページ範囲と失効条件](docs/search-options.md#件数と明示的な続き取得)

## X検索

「設定 → 検索プロバイダー」でFxTwitterを有効にし、「使う機能を選ぶ → X検索」をONにします。APIキーは不要です。

エージェントに `x_search` が追加されます。キーワードを渡すと投稿を検索し、X/Twitterの投稿URLを渡すとその投稿を取得します。

```js
x_search({ query: "AI from:example", sort: "latest", max_results: 8 })
x_search({ query: "https://x.com/jack/status/20" })
```

`sort` は `latest` または `top`、`max_results` は1〜100です。省略すると新着順・8件です。投稿URLを指定した場合は1件を取得します。投稿本文、投稿者、日時、取得できた反応数と元URLを返します。欠けている反応数を0にはしません。

キーワード検索はFxTwitter側で利用できない場合があります。404は「該当なし」と「取得不能」を区別できないため、エラーとして返します。投稿が存在しないとは判断しません。

FxTwitterは追加ツール専用です。通常の `web_search` の検索先には設定できません。

## 元の検索先に戻す

このプラグインを通常検索に使っているとき、プラグインを無効にするか削除すると、通常検索の検索先は切り替える前の値に戻します。その値は設定の `nativeSearchProvider` です。保存がない場合は `deepseek-official` です。`fetchProvider` など、ウェブ設定の他の項目は残します。起動中に設定画面から無効にした場合と、起動中にアンインストールした場合は、プラグインの解除時に戻します。

```sh
dsh plugin --profile web remove -w @aero123421/dsh-search-providers
```

ホストを止めた状態で上のコマンドを実行した場合は、profileに `.pnpmfile.cjs` が無いときに、このプラグインの起動時へ追加したフックが戻します。pnpmが依存関係の解決を終えた時点では、削除対象のpackageはまだprofileの `node_modules` にあり、解決済みlockfileからは外れています。フックはその時点で検索先を戻します。

次の操作では検索先を戻せません。削除や無効化の前に「DSH標準 → 通常検索に使う」で戻してください。

- profileに、このプラグイン以外の `.pnpmfile.cjs` が既にある。起動中の無効化とアンインストールでは戻せます。停止中の `dsh plugin remove` では戻せません。
- ホストを止めたまま、patchの該当項目だけを `disabled: true` にする、または選択中のbundleから外す。プラグインは起動しないため、解除処理は走りません。

アンインストール後はDSHを再起動します。保存したAPIキーは `$DSH_HOME/.credentials.yaml` に残ります。このファイルは同じDSH_HOMEの全profileで共通で、別のprofileが使い続けるため、アンインストールでは消しません。プラグインを無効にしても、更新しても、キーは残ります。キーを消す場合は、設定画面の「保存したキーを削除」を使います。この操作はDSH_HOMEの全profileに効きます。

別の `.pnpmfile.cjs` があるprofileでは、停止中のアンインストール時にフックが検索先を戻せません。起動中なら検索先は戻ります。保存したAPIキーは、どのprofileでも削除されずに残ります。

`0.3.2` へ戻す場合、新しい機能の保存項目はOFFでも旧版が読めないため、先に[バックアップと設定整理](docs/release-0.4.0.md#更新と旧版への復帰)を行ってください。

認識できない提供元や機能、読めない検索設定が保存されていても、プラグインの起動と一覧の取得は続けます。その項目は使わず、設定画面に理由と「保存項目を削除」を出します。削除するのはその設定項目だけで、APIキーは残します。通常の保存操作では、未知の提供元や未対応の機能を拒否します。

## 検証

`0.4.0` はローカルの型検査・217件のテスト・ビルド・互換／peer確認・ブラウザー確認に成功しています。実DSH `0.2.1-rc.2` ではソースと配布tgzを導入し、検索条件の保存・置換・リセット・競合拒否・Host再起動後の保持とUIを確認しました。公式 `0.3.2` から配布tgzへの隔離profile更新でも、既存設定・キーの有無・機能選択の保持を確認しています。既存版には導入・切替・出典表示・解除、および日本語・英語・中国語、明暗・狭い画面での確認もあります。[コマンド別の結果と未確認範囲](docs/release-0.4.0.md#検証)

今回Keenableのキーなし実APIで、`realtime` と `typescriptlang.org` のサイト条件を指定し、公式文書のURLを3件取得できました。他社の新条件・モード・バッチ・ページ送りは、実APIキー・実請求では未検証です。過去にFxTwitterの投稿URL取得も確認していますが、キーワード検索は404で、成功は未確認です。検索品質の比較、Windows・macOSの実機、Electron版は未検証です。

コードは[MIT](LICENSE)です。同梱するDSH UI部品の[著作権表示](LICENSE.DeepSeek)を保持しています。

## プラグインの更新

「設定 → 検索プロバイダー」の共通ヘッダーに実行版と更新操作を表示します。「更新を確認」はGitHubの正式Releaseを調べるだけです。「更新する」で選択した版を導入します。GitHub導入は明示したReleaseタグ、Releaseのtgz導入はSHA-256を照合した保存ファイルをDSHのplugin managerに渡します。既存の版固定は選択した版への固定に変更します。

`0.3.1` は `@deepseek-ai/dsh-*` の peer を `0.2.1-alpha.2` に固定しています。DSH `0.2.1-alpha.3` は起動時にその peer を満たさないプラグインを読み飛ばすため、`0.3.1` の設定画面と更新操作は出ません。`v0.3.2` を GitHub のタグか Release の tarball から導入し直してください。

HMR が有効な DSH は、導入済みパッケージを指す `installBundle` を `already-installed` で拒否し、profile は変更しません。更新処理はその結果のときだけ `removeBundle` のあと、同じ spec と以前の有効状態で `installBundle` します。取り外しでこのプラグインは停止します。導入の続きは、停止後も残る plugin manager に渡します。`stop-profile` はパッケージが残っている結果なので、そのあと導入します。それ以外の取り外し失敗では導入しません。HMR がない DSH では、従来どおり `installBundle` だけで上書きします。

`removeBundle` でパッケージが外れたあと、新しい版の導入が失敗または取消になり、一覧で不在を確認できた場合は、外す前の導入元と有効状態を別の request id で入れ直します。入れ直せたときは更新失敗として「以前の版を入れ直した」と表示します。再導入も失敗したときは、パッケージが外れたままであることと、Release か plugin manager から入れ直すことを表示します。一覧を読めないときは、不在と決めつけず、もう一つ導入しません。

APIキー、既定の検索先、プロバイダーのON/OFF、保存した検索条件、追加機能の選択は変更しません。有料プロバイダーや新機能を自動で有効化しません。既存版の差し替えはDSHの再起動が必要になる場合があります。「再起動してください」と「実行版の反映を確認しました」は別の状態です。

接続が切れた場合は導入を再送せず、操作IDで結果を照合します。結果を取得できないときは「結果が不明」と表示します。操作ID・候補版・結果だけをprofile内の`.dsh-search-update`に保存し、キーや検索設定は記録しません。tgz経路の検証済みファイルはprofileから参照されるため保持します。

plugin managerがない構成、読み取り専用、npm・ローカルの開発ディレクトリ等はReleaseへのリンクから手動更新してください。ダウンロード済みtgzは`aero123421-dsh-search-providers-<導入版>.tgz`の名前で配布経路を判定します。この名前だけで既存ファイルの発行者を保証するものではありません。新しい更新候補は固定repository・package・正式版を検査し、DSH互換性は本体と同じ規則（候補自身の`engines.dsh`があればそれだけを判定し、なければ`@deepseek-ai/dsh*` peer、要件のない候補は読み込み可）で判定します。可能なときはHost公開の判定へ委譲し、不適合時は必要なDSH要件を更新前に表示します。

更新操作のブラウザー内記録は接続先のプロファイルごとに保存します。再接続時はDSHが保持する最新の操作を優先し、結果不明の導入を再送しません。
