# 0.4.1 更新内容

`0.4.0` からの更新では、保存した検索設定とAPIキーを維持します。標準 `web_search`／`web_fetch` の引数、システムプロンプト、presetは変更しません。プラグインを無効にしても、更新しても、保存済みのAPIキーは残します。アンインストールでは、このプラグインが保存した `dsh-search-providers/` のキーを消し、通常検索の検索先を切り替える前の値へ戻します。

## 起動と設定

保存済みの提供元や機能がこの版で未知でも、型が違っても、項目が欠けていても、`null` でも、日付が実在しなくても、プラグインの起動と設定一覧は止めません。使えない項目は読み飛ばし、Hostのログに対象と理由を残します。設定画面にはその項目と「保存項目を削除」を出します。削除するのはその設定項目だけで、APIキーは残します。既知の提供元で検索設定だけが読めない場合は、その検索設定だけを外します。

設定画面からの保存は従来どおり検査します。未知の提供元、未対応の機能、実在しない日付は保存しません。

## 検索設定の操作

検索設定ダイアログの保存、リセット、キャンセルはダイアログのフッターに置き、項目が多くてもビューポート内に残します。APIキーの入力は、保存が成功したあとだけ空にします。保存に失敗したときは入力を残します。キーの値はログへ出しません。

## 結果のURLと期限

検索結果の出典URLと、本文取得の最終URLに、抽出入力と同じ公開URL条件を使います。ループバックやリンクローカル、クラウドメタデータ等の出典は結果から除き、検索結果は切り詰めます。最終URLが公開URLでない本文取得は失敗します。HTTPの45秒期限を超えた要求は `timeout` です。呼出し側の取消は期限切れにしません。

## 依存と表示言語

`@deepseek-ai/cordis` の peer は `^4.0.5-alpha.1`、`@deepseek-ai/schemastery` の peer は `^3.18.5-alpha.1` です。`4.0.5` と `3.18.5`、それぞれの `alpha.1` と `alpha.2` を含めます。開発時の依存は `alpha.1` のままです。中国語の辞書は残します。

このプラグインは `ja` の辞書を登録しますが、言語自体は追加しません。DSH `0.2.1-rc.2` の日本語表示には [dsh-japanese](https://github.com/Aero123421/dsh-japanese) が必要です。

DSH本体の設定画面は、幅390pxでも設定の見出し列を残します。プラグイン側のカード幅は、その残りの領域に従います。この版では本体の列幅は変えません。

## 無効化とアンインストール

DSH `0.2.1-rc.2` のbundle宣言に、アンインストール専用のcallbackはありません。`dsh plugin remove` はpnpmへ転送されます。npm 10とpnpm 10は、依存packageの `uninstall` scriptを実行しません。

起動中に無効化するか、起動中にアンインストールすると、プラグインの解除時に通常検索の `searchProvider` を `nativeSearchProvider`（無ければ `deepseek-official`）へ戻します。通常の終了では、bundleが選択されたままで項目が無効でなければ、検索先もキーも変えません。更新中は印を残し、検索先とキーを維持します。更新がpackageを消したまま終わった場合だけ、そのあとで検索先を戻しキーを消します。

キーの削除は、profileの `.pnpmfile.cjs` がpnpmの `afterAllResolved` から `dist/uninstall-hook.cjs` を呼ぶ経路です。この時点では `package.json` に依存が残っていても、解決済みlockfileからは外れ、packageのファイルはまだ `node_modules` にあります。フックはそこを見て削除します。profileに別の `.pnpmfile.cjs` がある場合は上書きせず、停止中のCLI削除では検索先もキーも自動では変わりません。ホストを止めたままpatchだけを無効にした場合も、プラグインが起動しないため検索先は戻りません。その二つは、削除前に「DSH標準 → 通常検索に使う」と「保存したキーを削除」を使います。
