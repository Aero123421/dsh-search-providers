# 0.4.2 更新内容

## 修正

- 読めない既知の保存値を未知の提供元と区別し、出典メタデータのURLにも公開URL条件を適用します。
- `10.com` などの公開名をIPv4の私設アドレスと誤認しません。埋め込まれた私設アドレス、ローカル向け名前、空ラベル、バックスラッシュと制御文字を含むURLを拒否します。Brave Goggleは検証済みの正規URLを保存します。
- 設定の改訂競合を明示し、通常検索の編集失敗時に保存した検索先を復元します。復元時は改訂を確認し、別画面の新しい変更を上書きしません。競合時や復元書き込みの失敗時は復元できないことがあります。
- 更新取得時の不正なリダイレクトパスを拒否し、HTTP失敗時に応答本体を破棄します。
- DSHの公開UI部品を使用し、検索設定ModalのフォーカスとEscapeをHostと共有します。
- 無効化・削除時は可能な場合に通常検索先を戻します。保存済みAPIキーは自動削除しません。明示的に削除してください。

## URL検査の限界と互換性

ホスト名中に私設IPv4が含まれると、未知のワイルドカードDNSも考慮して一律拒否するため、実際には公開の `10.0.0.1.example.com` も使えません。`10.com` や `192.168.com` は許可します。検査はDNS問い合わせを行わず、任意のホストの私設アドレスへの解決、DNS rebindingや抽出提供元によるリダイレクトを防ぐ保証はありません。実際の接続時には提供元の防護が必要です。

## 更新時の注意

pnpm 12では依存の公開後24時間制限による追加・更新失敗でprofileのnode_modulesが空になり、他のプラグインも読み込めなくなる既知の問題があります。pnpm 10を使用し、問題発生時はpnpm 10で `dsh plugin --profile web install` を実行してください。更新前にprofileをバックアップしてください。

実提供元APIキー、実アカウント、全OS・全機能組合せは未検証です。DSH自体のリリースはprereleaseを含みます。
